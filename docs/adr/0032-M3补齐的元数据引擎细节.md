# ADR-0032 M3 补齐的元数据引擎细节

- 状态：accepted（主管于 2026-10-22 按 design.md 开头的例外条款决定：都是规格漏写的技术细节，不改变 semantics.md 的任何承诺、不增删功能）
- 日期：2026-10-22
- 性质：契约层补齐（管理 API 的一个取值、init 写进磁盘的初始状态、一个错误码）与几处实现取值
- 是否触及契约层：**是**（初始 KV 有金样 `tests/golden/init_kv.golden`）
- 相关章节：design.md 3.2.8、3.3.3（角色权限）、3.3.4、3.4.1、3.4.3、3.7.2、7.1、7.2、9.2、附录 A；ADR-0019、ADR-0020、ADR-0030

## 背景

M3 实现单节点元数据引擎（raft-rs + redb）时，实现者遇到几处规格没写死的细节，按最小方案做了、加了金样或单测，并上报确认。每一条在 design.md 对应位置都有"实现注记（M3）"。

## 决定

1. **health 的 `meta_role` 取值**（7.1，ADR-0030 第 7 条只定了结构）：`leader` 只指**就绪**的 leader（本任期的空条目已应用、插件清单一致，3.4.1.4 规则 3）；新增 `candidate`，表示正在选举、或已当选但还没就绪；另有 `follower`、`learner`。只增不改。`wmfs dev wait leader` 等的就是 `meta_role = leader`。
2. **init 写的初始 KV**（3.4.3，index = 1）里规格没写的初值：根的 `parent = 0`（"无"）、`name` 为空；目录 `nlink = 2 + 子目录数`、`size = 直接子项数`（与 3.2.8 `InodeV1` 的注释、semantics.md 第 11 条一致）、`change_id = 1`；时间戳都取 init 的时刻；default 类 `weight = 1`、`priority = 1`、`failure_domain = 1`、`locality = 0`、其余 QoS 字段 0；NodeRecV1 的 `features` 为空、`host_id` 缺省取 `/etc/machine-id`、`hostname` 取 `/proc/sys/kernel/hostname`（读不到就写一行警告、留空）；根目录、`/home`、`/scratch` 的属主 = 运行 init 的进程的有效 uid/gid（为此 `base::sys` 新增安全封装 `euid_egid()`）。金样固定。
3. **`DebugPut`/`DebugGet` 被拒时回 `EACCES`**：不是 admin key、或 node.toml 没开 `debug_ops`。与 3.3.3 角色权限表的拒绝码一致。
4. **`meta/meta.redb` 的权限是 0600**，与 NODE、密钥文件一致。init 写完它先 fsync `meta/` 目录，再写 NODE（NODE 仍是"init 完成"的提交点）。server 启动时没有它就拒绝启动（绝不自己新建元数据库，坑 P14）。
5. **raft 线程一律按 tick 计时**（1 tick = 100 ms）：读闸门 500 ms 重发 = 5 tick、2 s 放弃 = 20 tick，写入规则 M2 的"每 1 s 补一次 Immediate" = 10 tick。这样确定性模拟不依赖真实时间。
6. **启动时严格**：GLOBAL `cluster` 或 `settings` 读不到、不存在或解不开 → 拒绝启动，不用默认值顶替。redb 错误：raft 线程与执行器线程上一律 abort（§0.2 第 5 条 fail-stop）；`meta-read` 线程上回 `EIO`（只是读，不影响已提交的状态）。
7. **插件清单不一致**（3.4.1.4 规则 3、3.7.2）：M3 只让节点"不就绪"并写一行列出差异的错误日志；"退出码 3"随 M8 的集群插件清单一起做。缺 GLOBAL `plugins` 也按不就绪处理。
8. **队列长度**：执行器输入队列 1024、`meta-read` 队列 1024（8 个线程）、raft 输入队列 4096，满了回 `BUSY`。
9. **确定性模拟的种子数**（9.2）：普通 `cargo test` 跑 200 个，`scripts/ci.sh` 与 `scripts/accept.sh M3` 跑 1000 个（`WMFS_SIM_SEEDS`）。测试用的 `MemCrashBackend` 除了"崩溃 = 丢掉没 sync 的写"，还有 `freeze_after(k)`：第 k 次 sync 处掉电、进程照常往下跑。
10. **回归检查**：M2 的"core/ 零改动"改为比较 tag `m2-base..m2`（design 2.1 的原意），否则从 M3 起 `accept.sh all` 会因为后面里程碑改 core 而失败。roadmap M3 演示命令在 `scripts/accept.sh M3` 之前加一行 `wmfs dev down`（与 M1 写法一致），`m3.sh` 的第一条检查是"19100/19180 端口空闲"。
11. **按 roadmap 留给后面的**：fail point `meta.reply.drop` 留到 M4（它的演示与验收都在 M4）；快照（`Storage::snapshot`、`install_snapshot`、pins、写入规则 M5）、raft-send 线程、SIGTERM 时的 `transfer_leader`、leave-joint 兜底（坑 P11/P13/P17）留到 M8。M3 里 `snapshot()` 回 `SnapshotTemporarilyUnavailable`，Ready 里出现快照算不变量破坏（abort）。

## 备选方案

- 把这些细节留到以后再定：第 2 条已经写进磁盘、第 1 条已经出现在管理 API 里，留着不定只会让后面的里程碑各猜各的。否决。
- 第 6 条在 `meta-read` 线程上也 abort：只读路径的错误不会破坏已提交的状态，abort 只会让一次读盘故障变成整个节点下线。否决。

## 后果

元数据引擎的初始状态与这些取值从 M3 起固定，初始 KV 由金样守住。后面的里程碑只增不改。
