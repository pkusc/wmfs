# ADR-0038 M7 补齐的属性与管理 API 细节

- 状态：accepted（主管于 2026-10-23 按 design.md 开头的例外条款决定：都是规格漏写的技术细节、已批准承诺的落实或分阶段的说明，不增删功能）
- 日期：2026-10-23
- 性质：契约层补齐（changelog 的 `extra` 键、管理 API 的 HTTP 细节、集群参数的取值范围）、几处实现规则，以及两条留给后面里程碑照做的规则（运行中调小租约、读句柄重新取 layout）
- 是否触及契约层：**是**（`meta.golden` 的 `ReopenHandle`、`api/src/types/mgmt/tests.rs` 的 JSON 金样，只增）
- 相关章节：design.md 3.1.4、3.2.8、3.4.4、3.8、3.10、3.11、7.1、7.2、8.7；semantics.md 第 1、4、7 节；ADR-0016、ADR-0023、ADR-0026、ADR-0029、ADR-0033、ADR-0036、ADR-0037

## 背景

M7 实现目录属性、递归用量（RSTAT）、管理 API、changelog 的长轮询与 `wmfs cluster set` 时，实现者与审查修复遇到下面这些规格没写死的地方，按最小方案做了、加了金样或测试，并上报确认。每一条在 design.md 对应位置都有"实现注记（M7）"。第 5、7 条是主管这次补的规则，由后面的里程碑实现。

## 决定

1. **changelog 的 `extra`**（ADR-0029 的补充）：`AttrSet` = `key`/`old`/`new`，`AttrUnset` = `key`/`old`，`ClusterSet` = `name`/`old`/`new`。值都是显示形式（例如 `1M`、`0s`），没有旧值时 `old` 为空字符串。
2. **管理 API 的线上细节**（7.1）：
   - 只有**就绪的**元数据 leader 回答。别的节点回 409 `{error: "not_leader", message, leader}`（`leader` 是 leader 的管理地址，命令行自动跟随）；还没有 leader、或 leader 刚当选还没就绪，回 503。
   - 状态码：`ENOENT` → 404，`EACCES`/`EPERM` → 403，`NOT_READY`/`RETRY`/`BUSY` → 503，`INTERNAL`/`EIO` → 500，其余 → 400；changelog 中要的那一段已被修剪 → 410 `GoneReply {error, message, oldest}`。
   - 查询参数里的路径按百分号编码，只认 `%XX`（两位十六进制），坏的编码 → 400。数字参数写错 → 400 `einval`，只有没给时才用默认值。
   - 按 3.8，读对所有已认证的 key 开放，写只接受 admin，所以路径以 uid 0 解析；changelog 里记 uid 0 与这把 key 的租户。M10 的 path-caps 要同样限制按路径的查询（`get`、`usage`、`status`）。
   - 写请求遇到 `RETRY`/`BUSY`/`NOT_READY` 时自动重试，最多 5 次。结果不确定（批次丢失，`NOT_LEADER`）或重试用尽时，按执行器的码回 409/503，不把闭包自己的业务错误当成结论。
   - `ChangelogPage {events, next, last_seq}`：`next` 是下一页的 `after`，`last_seq` 是此刻最新的 seq。`StatusAttr.actual` 现在只有 `new_files`（第 9 条），M11 只增字段。
   - changelog 长轮询：每个节点同时最多 2 个请求在等，第 3 个起立即返回现有的记录（可能是空页）；`limit` ≤ 1000，`wait_ms` ≤ 30 s；新记录提交后（`after_apply`）唤醒等待者。游标名是 1–64 个 `[A-Za-z0-9._-]`，提交的 seq 不能超过最新的 seq。`wmfs changelog tail -f` 收到不到 1 s 就回来的空页时，先等 1 s 再问，不忙等。`wmfs_changelog_consumer_lag` 由 cluster-mgr 每 5 s 刷新一次。
3. **属性设置与查询的报错**（3.8）。下面几种都是拒绝，3.8 的"未知属性被拒绝"照样成立，只是错误码与提示更具体：
   - 后面的里程碑才实现的属性（`quota`、`compress`、`trash`、`qos`……）与二期的属性 → `EOPNOTSUPP`，提示写明在哪个里程碑实现；`consistency=strong` → `EOPNOTSUPP`（M12）；`wasm:` 开头的值 → `FEATURE_UNSUPPORTED`；别的名字 → `EINVAL`「未知属性 k」。`unset` 与 `set` 规则相同。
   - 没有插件消费的属性被拒绝：键的 consumers 含 `core` 时总能设置，否则要有一个已启用插件的 manifest 声明了它。`checksum` 还要求对应算法的 transform 插件已启用。启动时核对插件 manifest 里的属性名都是注册表认识的键。
   - `wmfs get <路径> <键>`：回复里没有这个键 → `EINVAL`「没有属性 k（能查的有 …）」，退出码 1。
   - "成功但警告"只检查这次设置的键：设了 `replicas` 或 `class` 才查故障域数，设了 `stripe`、`replicas` 或 `class` 才查可用链数。设了 `class` 或 `replicas` 时另附一句提醒：协调器在 M11 实现，现在不会转换已有文件。
   - `consistency` 连同子键 `attr_ttl` 在 DIRATTR 里存成一个值（`cto` 或 `cto,attr_ttl=<毫秒>`），随主键一起继承。
   - `AttrOut.consistency`/`ttl_ms` 由管辖目录决定：目录取它自己，文件取主父目录。孤儿（nlink = 0）的主父目录已删掉时取根目录（先点查主父目录的 inode 还在不在）。
4. **集群参数的取值范围**（3.2.8）：时长精确到毫秒，不超过 30 天。租约至少要盖住 3 次续租：`session_lease` ≥ 10 s（会话心跳每 3 s 一次），`target_lease` ≥ 3 s（target 心跳每 1 s 一次）。更短的租约永远续不上，M9/M10 按它回收时会不停地驱逐客户端、摘掉 target。`cap_ttl` ≥ 1 s，`bg_bytes_per_sec` > 0。改了的批次 `map_epoch += 1`，每项一条 `ClusterSet`。
5. **运行中调小租约**（规格没写；M7 只改值、不回收。M9 的 target 租约回收与 M10 的会话驱逐照下面做）：
   - 原因：持有方要到下一次心跳拿到新的集群图，才知道租约变短了，在那之前它按旧值计时。授予方马上按新值回收的话，一个刚失联的持有方可能还在按旧值干活（例如还在写），而授予方已经把它驱逐或摘掉了。
   - 调大：立即生效。
   - 调小：同一个批次在 GLOBAL 里写一个新键 `settings_prev`（`ClusterSettingsV1`，版本 1，只增），记下修改之前的值。已经有 `settings_prev` 时，每一项取两者中较大的。
   - 授予方判定过期用的时长 = max(当前值, `settings_prev` 里的值)（有 `settings_prev` 时）。
   - 删除 `settings_prev`：leader 在应用这次修改、再过一个旧租约周期之后（按单调时钟），写一个批次把它删掉。新 leader 上任时看到它还在：计时重置（3.4.1.10）按 max 给宽限，上任一个旧租约周期之后再删。
   - 为什么安全：还连着的持有方一次心跳之内就知道了新值。失联的持有方最后一次成功心跳在修改之前，它最晚在修改后 0.8 × 旧值时自停，而 `settings_prev` 至少留一个旧租约周期。
   - `cap_ttl` 不需要过渡：已经签出的 cap 带着自己的过期时间，新值只影响之后签的 cap。
   - 代价约 20 行。测试：调小 `session_lease` 之后立刻冻结一个客户端，它在旧租约期满之前不被驱逐。
6. **目录深度**：命名空间不限制深度。沿 parent 指针走的步数上限 `attrs::MAX_DEPTH = 65 536` 只用来发现损坏的 parent 指针（成环）。嵌套超过它的目录里，操作回 `EIO`（`INTERNAL`）。semantics.md 第 7 节"目录属性与递归用量"一项写明。
   - 不做成 mkdir/rename 时报错的"真正的限制"：rename 一个目录时要知道被移动子树有多高，做不到 O(1)。
   - 这个上限现实中用不到：Linux 一条路径最长 4096 字节（按路径最多约 2048 层）；每个修改要沿祖先更新递归计数（O(深度)），几万层深的树本来就不实用。
7. **读句柄重新取 layout 也用 `ReopenHandle { write: false }`**（M8 第一步修，约 1 行）。
   - ADR-0036 第 5 条的"属主自己的句柄照常可用"包括读句柄。ADR-0037 第 4 条只写了写句柄，是主管的疏漏，M7 照它做了，所以属主去掉自己的读权限之后，读句柄碰上 layout 变化会得到 `EACCES`。
   - 对非属主，`ReopenHandle { write: false }` 授权用 `Handle { read: true }`，与 `Open` 只读的规则相同，结果不变。按路径截断仍用 `Open(O_WRONLY)`，不借属主放行。
   - 测试：属主只读打开自己的文件，`chmod 0200` 之后另一个挂载把它截断到 0 再写，读句柄照常读到新内容；非属主在 `chmod o-r` 之后碰上 layout 变化，回 `EACCES`。
   - 一并写明（M7 已做，design 8.7 已注）：重新取 layout 被授权拒绝 → 如实回 `EACCES`（M6 把它改写成 `ESTALE`，M7 去掉了）；只有重试 `STALE_RETRIES` 次仍拿不到稳定的 layout 才回 `ESTALE`。
8. **递归用量（RSTAT）的口径**（3.10）：
   - `bytes` 是普通文件的逻辑大小之和；`per_class` 只计普通文件。
   - 硬链接只在主链接所在的目录计一次；rename 只有主链接换了目录才搬计数。
   - 孤儿在删光链接时扣除，之后再写也不计（与 `du` 一致；配额怎样计删除后仍打开的文件，由 M10 按 ADR-0026 定）。
   - 增量合并后为 0（例如长度不变的提交）时不写记录。
   - 离线 `wmfs debug rstat-check` 要先停节点（redb 不允许两个进程同时打开）。
9. **`wmfs status` 的"实际"在 M11 之前只到"新文件"一层**：
   - 只给出这个目录下的新文件此刻能得到的值：replicas = min(声明, 故障域数)，stripe = min(声明, 可用链数)，其余等于声明值。不扫描子树，所以也没有令牌桶限速。
   - 逐文件的统计与截断标记随 M11 的 `bg/status.rs` 加入。semantics.md 第 1 节已写明，属于分阶段的说明，M11 做完后改掉。
   - 只把含 `replicas` 或 `stripe` 的目录计入 1000 个的上限，超过时在 `warnings` 里明确说一句。
10. **属性解析缓存的正确性**（3.8，`attrs.rs` 的文件头）：
    - 缓存整体打 `attr_epoch` 标签。任何目录 rename（同一目录内改名也算）、删掉带 DIRATTR 的目录，都令 `attr_epoch += 1`；M13 修改存储类时也必须这样。
    - 执行器的批次没有成功应用时，清空缓存。一个闭包里 `attr_epoch` 加一之后，不再解析属性。
    - 缓存按"生效属性每项 1、祖先链按长度"计大小，上限 2¹⁷ 个单位。
11. **RECONCILE_Q 从 M7 起开始写**：`class`/`replicas` 的 set/unset 写 reason 1，目录 rename 写 reason 2（3.1.2、3.8）。消费者是 M11 的协调器，在那之前队列只积累，每次一条小记录。
12. **命令行**（7.2）：
    - 挂载点路径按 mountinfo 的来源前缀 `wmfs:` 识别（容器里 root 直接挂载时类型是 `fuse`），管理地址从根目录的虚拟 xattr `user.wmfs.mgmt` 读。
    - 查询命令的 `--json`：每个回复一个 JSON（`changelog tail` 每页一行，边读边打印）；出错时输出 `{error, message}`。
    - `wmfs cluster` 的子命令在 `cli/src/cluster.rs`。
13. **ADR-0037 第 12–14 条已在 M7 第一步修完**：`ReopenHandle`（写句柄，读句柄见第 7 条）、readdir 的 `..` 指向父目录、`wmfs dev mount` 失败时保留 `mount.log`。

## 留给后面的
