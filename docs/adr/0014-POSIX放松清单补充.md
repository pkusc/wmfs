# ADR-0014 POSIX 放松清单补充

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 偏离条款：理念文档 8.2"POSIX 放松清单（必须写进用户文档）"——新增条目；第 3 章 [固定]"命名空间语义与一致性模型"（契约本身的首次定义见 ADR-0028）
- 是否触及契约层：**是**（对外语义承诺）
- 批准类别：**需批准**（A 栏：要你拍板）；确认批次 1（M4 开工前：⑪ 从 M4 起生效，⑦⑩ 从 M5 起，① 从 M6 起）
- 相关章节：design.md 3.1.1、3.5.3；semantics.md 3.3

## 背景

部分限制来自所用的库（fuser 0.18 不把 `FUSE_LK_FLOCK` 传给文件系统、不处理 FUSE INTERRUPT），部分来自首发为了简单正确而做的取舍。原则 7 要求它们全部写进对外文档。

## 决定

接受并写进 semantics.md 的 16 条新增放松：① cto 属性/目录项缓存 ≤ `attr_ttl`（目录属性，默认 1 s）；② flock 与 fcntl 共用锁空间；③ `F_SETLKW` 不可被有处理函数的普通信号打断（致命信号在 ≤ 1 s 内结束等待）；④ 无死锁检测；⑤ mmap 写的配额错误在写回时报告；⑥ strong `O_APPEND` 的读者可能短暂看到零、`lseek` 位置可能不精确；⑦ 缩短截断不是崩溃原子的（先数据后长度）；⑧ 跨节点并发 truncate 与 write 可能"长度来自写、数据为零"；⑨ 所有副本同时掉电时未 fsync 数据可能丢失（即使曾被读到）；⑩ 客户端在提交长度前崩溃时，未提交的数据可能在之后的扩展中暴露；⑪ 目录 st_size = 条目数、inode 号不复用、generation 恒 0；⑫ mtime/ctime 用 leader 时钟、cap 需要 NTP 级时钟；⑬ relatime 的 atime 更新尽力而为；⑭ 阻塞等锁由客户端轮询（50 ms 起、上限 1 s），**不保证先来先得**；⑮ inotify/dnotify 与 `F_SETLEASE` 只在本节点有效；⑯ 回收站文件仍计入配额、删除目录树时目录结构不保留。

## 备选方案

- ②③：给 fuser 上游提 PR 暴露 `lk_flags` 与 INTERRUPT，届时去掉这两条。
- ⑦⑧：用"先写截断计划、后执行、再确认"的协议——多三种消息与一种错误码，仍不能消除 ⑧。首发不采用。
- ⑬：每次 relatime 更新都同步提交——代价高。不采用。
- ⑭：服务端 FIFO 等待队列——要在执行器里挂起已经执行过的闭包、重新生成授予操作，还要处理去重与超时，约多 150 行，而且容易实现错。不采用（原来的 ⑭"audit=all 的 open 多一次元数据写"随 open 审计一起删掉了）。

## 后果

pjdfstest 的预期失败清单（`tests/pjdfstest-expected.txt`）的每一项都必须对应到本 ADR 或 ADR-0013 的某一条；清单外的失败不能发布。
