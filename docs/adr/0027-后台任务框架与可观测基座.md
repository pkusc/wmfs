# ADR-0027 后台任务框架与可观测基座

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 性质：契约层首次定义（理念文档第 3 章"后台任务框架""可观测性基座"；5.1"声明 vs 实际"；5.3 协调器；原则 6）
- 是否触及契约层：**是**
- 批准类别：**需批准**；确认批次 0（B 栏：技术契约。M0 就实现指标注册表与 fail point，M5 就有后台调度器骨架与 gc 任务）
- 相关章节：design.md 3.10、3.11、7.3

## 背景

理念文档把"后台任务框架"（可限速、可断点续跑、可观测；协调器是第一个实例）和"可观测性基座"（trace id 贯穿、计数器注册表、changelog 流、内建 fail points）都列为本体契约，并要求"系统永远能回答声明是什么、实际是什么、差距在哪"、"所有策略旋钮都能在 dashboard 上看到声明与实际"。指标注册表与 fail point 既要给 core 用，也要给不能依赖 core 的进程外插件（wmfs-mgr）用。

## 决定

1. **后台任务**：`BgTask` trait（`kind`、`runs_on`（MetaLeader / EveryDataNode）、`interval`、`step`）；`step` 每次只做一小步且必须幂等；游标由 core 持久化（leader 任务存 KV 的 TASK 记录，节点任务存本地 `run/task-<kind>.cursor`）；任务级与节点级令牌桶限速，后台数据流量走 QoS 低优先级队列；leader 切换后从游标续跑；`wmfs task list/show/pause/resume/run/set`；进度、积压、速率、错误都是指标。
2. 遍历器（子树 DFS、全量扁平扫描）与迁移原语（`pending_epoch` 登记 → 按新布局复制 → 持久化 → CAS 切换 → 旧 epoch 进 GC；失败则新 epoch 进 GC）由 core 提供；写打开的文件被跳过并在内存里计时，超过 24 h 发 `PolicyViolation`；协调器是第一个实例，`declared()` 与 `wmfs status`、tiering 共用。
3. **声明 vs 实际**：每个属性的"实际"有明确来源（design.md 3.10 的表：逐文件比较 layout、RSTAT 与配额状态、节点上报的 QoS 欠额、回收站计数、tier/ttl 积压、审计游标落后条数；consistency/acl.default/locality/inherit 实际 = 声明），`GET /api/v1/status` 对每个键返回 `{key, declared, source, effect, actual, mismatched}`。
4. **可观测**：trace_id 由客户端为每个 FUSE 操作生成，写在帧头、贯穿元数据与链上转发、写进 changelog；每进程 65 536 个 span 的环形缓冲与慢请求日志（客户端的 span 只进它自己的慢日志）；`wmfs trace <id>` / `--recent` 汇总各节点；计数器注册表（原子计数、Prometheus 文本、受控的标签基数）与 fail point（函数 `fail_point(name: &str)`，未启用时一次原子读；可由环境变量或测试 API 配置，覆盖每个钩子与关键步骤）放在只依赖 serde 的 `wmfs-api` crate，core 与 wmfs-mgr 共用；策略违约既有指标也写 changelog 事件；changelog 长轮询（每节点同时最多 2 个）+ 消费者游标 + 显式缺口（410）；时钟可注入偏移与速率。

## 备选方案

- fail point 用宏：违反"除 derive 外不写宏"的约定。否决。
- 事件流用推送（服务端主动推给订阅者）：要维护订阅者连接与重发状态；长轮询 + 游标更简单、天然至少一次。否决。
- 指标与 fail point 留在 core、进程外插件不做：违反"每个插件都有 fail point 与指标"（理念文档 4.3.4）。否决。
- "声明 vs 实际"只覆盖 class/replicas/compress/encrypt：做不到第 9 章"所有策略旋钮"的成功标准。否决。

## 后果

所有后台工作都可暂停、可续跑、可观测；fail point 让单机无 root 也能模拟分区、时钟异常与坏盘；dashboard 上每个属性都能看到声明与实际。
