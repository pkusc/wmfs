# ADR-0023 租约、能力令牌与两阶段客户端驱逐

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 性质：契约层首次定义（理念文档第 3 章"复制、成员、选举、fencing"中的租约与客户端驱逐、脑裂防护；"事务与锁原语"中的租约）
- 是否触及契约层：**是**
- 批准类别：**需批准**；确认批次 0（B 栏：技术契约；M4 起实现会话，M5 起实现能力令牌，M9 起实现数据节点租约，M10 起实现驱逐）
- 相关章节：design.md 3.3.5、3.4.4、3.4.5

## 背景

单阶段驱逐（在驱逐批次里立即释放锁）时，被驱逐客户端在自停前已发出的数据写，可能在数据节点拿到新集群图之前落地，覆盖新锁持有者的数据（fcntl 锁保护的共享文件、IO500 hard 模式会被静默写坏）。

## 决定

1. 三种租约：客户端会话 30 s（每 3 s 心跳）、target 成员资格 8 s（每 1 s 心跳）、能力令牌 10 min（用到 80% 续期）。时长存在复制状态里，全集群一致。
2. 一律"**持有方先自停、授予方后回收**"：持有方从"最近一次成功心跳的发送时刻"起 0.8 × 租约后自停；授予方从"最近一次收到心跳"起 1.0 × 租约后回收。只要求单调时钟速率差 < 20%，不要求时钟同步。续租必须经过 ReadIndex；leader 切换后所有计时重置。
3. 能力令牌 = postcard(CapV1) ‖ HMAC，带 ino、epoch、权限、会话、租户、**layout 的链列表**、QoS 键、变换参数、过期时间；数据节点在 io 线程执行请求时校验（不是入队时）。
4. **两阶段驱逐**：① 会话标为 Evicting、写入被驱逐列表、`map_epoch` 加一（之后该会话的元数据请求被拒，数据节点拿到新集群图后拒绝其 cap）；② 等所有 Up 的 target 都在心跳里报告已看到该 map_epoch（或已超过 target 租约未心跳、已自我隔离）；③ 才释放该会话的锁、删除会话记录（被驱逐记录保留 24 h，`wmfs session list` 显示 EVICTED）。别的客户端的锁轮询随后就能拿到锁。
5. 客户端从长时间停顿恢复后，任何操作先等一次续租结果；被驱逐 → 旧句柄 `EIO`（不静默），新建会话。

## 备选方案

- 单阶段驱逐：有上述窗口。否决。
- 锁级 fencing token：POSIX 锁没有地方携带令牌（NFS 同样如此）。不可行。

## 后果

驱逐至少需要 30 s + 集群图传播；能力令牌依赖墙钟（容差 5 min，要求 NTP）。
