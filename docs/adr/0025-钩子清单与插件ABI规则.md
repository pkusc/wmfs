# ADR-0025 钩子清单、altitude、manifest、插件 ABI 版本规则与集群插件清单

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 性质：契约层首次定义（理念文档第 3 章"钩子管线与插件 ABI"；4.1、4.3）
- 是否触及契约层：**是**
- 批准类别：**需批准**；确认批次 0（B 栏：技术契约）
- 相关章节：design.md 1.3、3.7、3.12、4.10、4.13

## 背景

理念文档 4.1 给出了钩子清单与管线顺序，4.3 给出了插件硬规则（manifest 必填字段、不持有本体不知道的状态、热路径不阻塞且有时间预算、每个插件有 fail point 与指标、顺序由 altitude 决定、ABI 不兼容即拒绝加载）。这些要落成具体的 trait、数据结构与启动时的校验。还有一个理念文档没有直接写、但原则 7 要求的问题：authz、quota、placement 在元数据 leader 上执行，qos、transform 在数据节点上执行——如果各节点 node.toml 里启用的插件不同，leader 一换、或者请求落到另一个数据节点，已设置的策略就会被静默跳过。

## 决定

1. 钩子清单与管线顺序完全按理念文档 4.1；每个钩子的 Rust trait 签名见 design.md 3.7.3（全部对象安全，跨模块用 `Arc<dyn …>`），跨模块调用的接口签名见 3.12。要点：`Transport::listen` 读插件自己的部署配置并返回要公布的地址；握手由 core 在 `Conn` 上执行（`mark_authenticated` 之后传输才做单边操作）；`Conn::send` 只由 core 的每连接写线程调用；`PlacementInput` 带 `size_hint`（理念文档 4.1"大小提示"）；`QosPlugin` 不阻塞，睡眠与唤醒归 core。
2. altitude 区间与组合规则见 design.md 3.7.2；transform 子序固定（checksum 700–729 → compress 730–759 → encrypt 760–789）；唯一型钩子恰好一个；qos 只允许一个活跃；placement 取 `min(stripe, 可用链数)` 条。
3. `Manifest` 必填理念文档 4.3.1 的 7 个字段，另加 `attrs`（消费的目录属性键）、`budget_ns`（热路径预算）、`fail_points`；每个插件目录另有 `manifest.toml`，测试断言两者一致。embedded-kv 的代码在 core（元数据 Raft 是契约），但同样有 `plugins/embedded-kv/{manifest.toml, docs.md}`。进程外插件（wmfs-mgr）的 manifest 由 mgr 宿主在启动时校验（ADR-0017）。
4. 启动时 `PluginSet::validate()`：区间、唯一性、`abi_version == CORE_ABI_VERSION`（不兼容即拒绝启动，不尝试适配）、**所有热路径插件（含 transport、chunk_store）都有明确的 `budget_ns`**（transport/chunk_store 约 100 ms，超出照常计数，没有豁免）、fail point 声明、配置键必须在 `config_schema` 里。配置只能启停插件，不能改顺序；插件配置只放部署参数（例如 quota 插件没有任何配置项，宽限期缺省值在属性注册表里）。
5. 每次钩子调用由 core 包一层：fail point `plugin.<name>.<hook>`（名字在注册时拼好，`fail_point(name: &str)`）→ 计时 → 超预算计数 → 错误计数。transport 的 fail point 包在写线程对 `Conn::send` 的调用外层，触发 = 连接作废。
6. **集群插件清单**：authn、authz、quota_admission、qos、placement、codec、transform、bg_task 上启用的插件（`钩子:名字`，含动态库；不比版本，以便滚动升级）记在复制状态 GLOBAL `plugins`。init 写入；`wmfs cluster plugins add|remove`（admin，写 changelog，`map_epoch + 1`）修改；每个节点拿到集群图时比对、leader 就绪时比对，不一致 → 列出差异并退出（等同拒绝启动）；join 时不一致直接拒绝。逃生口：`wmfs server --adopt-local-plugins` 让一个元数据节点在当上 leader 时把清单改成自己的。
7. 插件注册表只在 `cli/src/registry.rs`；新增插件 = 新目录（或独立 crate）+ 注册表一行 + 一个 feature，**core 一行不改**。
8. 策略求值点 `PolicyEvaluator`（CreatePlacement、TierCondition、AuditFilter、AttrValidate）为二期 WASM 预留，永不进入每次读写路径。
9. 动态库 C ABI 见 ADR-0012。

## 备选方案

- 每个插件一个 crate：约 27 个 Cargo.toml，太碎；`wmfs-plugins` 内每个插件一个目录、一个 feature 已能隔离（测试扫描源码禁止插件互相 use）。否决。
- 全部插件都走动态库：所有热路径 trait 都要稳定成 C ABI，`Buf` 所有权要跨 FFI，风险过大。否决（ADR-0012）。
- 允许配置改变插件顺序：正是 GlusterFS translator 的反面教材（理念文档原则 2）。否决。
- fail point 用宏实现：违反"除 derive 外不写宏"的约定，函数加一次原子读的开销已经可以忽略。否决。
- transport、chunk_store 只记直方图、不设预算：与"热路径每次调用都有时间预算"（4.3.3）矛盾。否决。
- 不做集群插件清单、只在文档里要求"各节点配置一致"：配错就静默跳过策略，违反原则 7。否决。
- 清单里比较版本：每次升级二进制都会让节点与清单不一致，滚动升级无法进行。否决。

## 后果

增删钩子或改 trait 签名 = 契约变更（`CORE_ABI_VERSION + 1` + ADR）。修改插件集合需要用新配置重启全部节点；配错的节点会退出而不是带病服务。
