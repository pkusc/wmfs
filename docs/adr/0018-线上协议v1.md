# ADR-0018 线上协议 v1：帧、握手、能力协商、消息与错误码

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 性质：契约层首次定义（理念文档第 3 章"持久化格式与线上协议"中的消息帧、能力协商、feature flags；第 7 章 [默认]"自定义二进制帧 + 能力协商 + 版本号；同一协议跑 TCP 与 RDMA"）
- 是否触及契约层：**是**（不可逆的协议格式）
- 批准类别：**需批准**；确认批次 0（B 栏：技术契约）
- 相关章节：design.md 3.2.10、3.2.11、3.3、3.6.4、3.12

## 背景

协议一旦有节点在跑就很难改，必须从第一天带版本号与能力协商。理念文档第 9 章的成功标准"新增一个传输插件不改本体任何一行"要求协议与 core 的记录里不能有任何专属于某个传输的字段。

## 决定

1. 48 字节小端帧头（magic `WMF1`、proto_major、kind、msg_type、req_id、trace_id、flags、span_id、body_len ≤ 1 MiB、bulk_len ≤ 16 MiB + 128 KiB、body/bulk/header 三个 crc32c）。body 永远是小结构；**大块字节一律走 bulk**（chunk 数据、packed chunk、RaftMsg 的 protobuf）。TCP 下 bulk 紧跟 body；支持单边操作的传输用描述符表（`BULK_REMOTE`：n ≤ 16 个 `{addr, rkey, len}`；`REPLY_REMOTE`：响应写到哪里），由接收请求的一方发起 READ/WRITE；这两个标志位只由传输插件设置与解析。
2. 握手 Hello / Challenge / Auth / Welcome 由 **core** 在传输交出的连接上执行（与传输无关）：版本区间协商、feature 位取交集、`required` 位不满足即拒绝；HMAC 挑战-应答双向认证（ADR-0009）。**角色只有一套编码** `Role { Admin = 1, Client = 2, Server = 3 }`（线上存 u8）：key 0 只能是 Server，其他 key 的 Hello.role 必须等于 KEYMETA 里的角色，否则 `AUTH_FAILED`。
3. 消息族：MetaCall、DataCall、PeerCall、NodeCall、RaftMsg、SnapshotFetch、Ping；0x0600–0x06FF 留给传输插件私有（不透明字节，只出现在插件自己的引导连接上，例如 RDMA 的 QP 信息交换，**不含 rkey**）。每个族有固定的角色权限表（PeerCall、RaftMsg、SnapshotFetch 只有 Server 能发；client 的 NodeCall 只能 GetClusterMap）。body 是 postcard 编码的 Rust 结构/枚举。
4. **传输选择**：控制族（MetaCall、NodeCall、RaftMsg、SnapshotFetch）永远走 `control_scheme`（默认 tcp）；数据族（DataCall、PeerCall）在双方都公布了 `data_scheme` 时走它——客户端要求的 scheme 对端没有公布就报错，服务端之间退回 control_scheme 并告警。节点地址在 `NodeRecV1.addrs` / `JoinReq.addrs` 里是 `Vec<(scheme, 地址)>`，由各传输插件的 `listen()` 返回；core 只做字符串比较。协议 feature bit0 叫 `BULK_REMOTE`。
5. 演进规则：同一 msg_type 的 body 结构永不改变；枚举只在末尾加变体，且只在对端握手声明支持（feature 位）后发送；不认识的 msg_type/变体 → `FEATURE_UNSUPPORTED`，不断开；每种消息一份"金样"字节测试（M0 生成）。
6. 消息里的几处约定：`ReadDir.limit ≤ 1024` 且回复编码 ≤ 512 KiB；`SetLock` 永远非阻塞（冲突回 `EAGAIN`，F_SETLKW 由客户端轮询）；改了 size 的 `SetAttr` 回 `Opened(OpenOut)`；`AttrOut` 带 `ttl_ms`；`Joined` 回复带当前集群图；`ClusterMap` 带集群插件清单与集群警告；心跳带各 target 的物理盘 `phys_devs` 与 QoS 保底欠额。
7. 错误码：1–255 为 Linux errno（另有本地产生的 `ECONNRESET`、`ETIMEDOUT`），1000–1020 为集群码（design.md 3.3.7；1015 保留未用），客户端按表重试；**传输层的任何错误都按"连接断开"处理**（关闭连接，在途调用重连后重试），只有"帧超过该传输的上限"只让单个请求失败。能力令牌 `CapV1` 的线上格式 = postcard ‖ 16 字节 HMAC。

## 备选方案

- gRPC/protobuf：需要 async 或 C++ 核心（ADR-0005）。
- Cap'n Proto / FlatBuffers：零拷贝更好，但是新依赖、对新手陌生。
- JSON：慢、无法零拷贝。
- 记录里给 RDMA 留专门的地址字段、协议里放 RdmaSetup 消息：每加一种需要公布地址的传输都要改 core 的不可逆格式，违反第 9 章成功标准。否决。

## 后果

协议发布后不可逆；任何变化走"新变体 + feature 位 + ADR"。
