# ADR-0033 M4 补齐的命名空间与会话细节

- 状态：accepted（主管于 2026-10-22 按 design.md 开头的例外条款决定：都是规格漏写的技术细节，不改变 semantics.md 的承诺、不增删功能；第 5 条比规格更严）
- 日期：2026-10-22
- 性质：契约层补齐（`leader_hint` 的取值、两组标志位的数值、init 写进磁盘的 TargetRecV1、会话协议的用法规则）与几处实现取值
- 是否触及契约层：**是**（`constants.golden`、`init_kv.golden` 已更新）
- 相关章节：design.md 3.1.1、3.3.1、3.3.4、3.3.7、3.3.8、3.4.1.4、3.4.2.1、3.4.3、3.5.1、7.2；ADR-0009、ADR-0014、ADR-0016、ADR-0028、ADR-0029、ADR-0032

## 背景

M4 实现命名空间、会话、去重、changelog、集群图与 posix-mode / label-match 插件时，实现者与审查修复遇到下面这些规格没写死的地方，按最小方案做了、加了金样或测试，并上报确认。每一条在 design.md 对应位置都有"实现注记（M4）"。

## 决定

1. **`leader_hint`**（3.3.1 的 `ErrorBody`、3.3.7）：取 leader 在 control_scheme 上的 rpc 地址 `"host:port"`；只在 `NOT_LEADER` 时由 core 自动填；不知道 leader、或集群图里查不到它的地址时为 None。客户端拿到 hint 立即换过去重试；没有 hint 时退避后在认识的节点（种子地址 + 集群图）之间轮换。core 里没有 HTTP 客户端，所以"按 health 找 leader"由 CLI 在建连之前做。
2. **标志位的数值取 Linux 的**：`RENAME_NOREPLACE = 1`、`RENAME_EXCHANGE = 2`、`RENAME_WHITEOUT = 4`（不支持，回 `EINVAL`，3.1.1）；`XATTR_CREATE = 1`、`XATTR_REPLACE = 2`。金样 `tests/golden/constants.golden`。
3. **init 的 target**（3.4.3）：`wmfs init --target PATH[:label,...]` 写 TargetRecV1，初值为 `node = 1`、`state = 1`（Up）、`last_up_ms` = init 的时刻、`phys_devs` 空、`boot_id = 0`、`capacity` 取 node.toml 的 `[[target]]`（0 = 不限）。重复或互相嵌套的 `--target` 被拒绝。不带 `--target` 就没有 target：新建文件回 `ENOSPC`，集群警告"没有可用的 target"。`wmfs dev up` 给每个节点一个默认 target `<节点目录>/targets/1`（容量上限 20 GiB）。target 目录与 TARGET 超级块（3.2.3）随 M5 的 chunk_store 一起写。金样 `init_kv.golden` 已更新。
4. **会话协议的用法规则**（3.3.4、3.4.1.4）：
   - `SessionOpen`/`SessionClose` 用 seq 0，不进去重表（本身幂等；会话关闭之后带 seq 的重试拿到 `SESSION_EVICTED`）；其余修改型请求 seq = 0 或 session = 0 → `EINVAL`（否则既没有去重，也绕过了会话检查）。
   - 会话属于打开它的那把 key：别的 key 拿这个 session id 发请求回 `EACCES`。
   - 会话操作不做 uid 范围检查，身份一律记为 nobody（65534），changelog 里也是 nobody。
   - 客户端的在途窗口按 seq 的范围计：新 seq 必须小于"最小在途 seq + 256"，否则等待。这样一个等超时重试的请求不会被后面的请求挤出去重窗口。
5. **`root_squash` 同时映射 gid**：uid 0 → 65534、gid 0 → 65534，并去掉附加组 0（与 NFS 一致；规格原文只写了 uid）。
6. **去重命中怎么看**：服务端新指标 `wmfs_meta_dedup_hits_total`（引擎启动时注册）加一行 INFO 日志"去重命中"，这是确凿的证据。协议里没有"去重命中"标志，加标志要改帧格式，不值得；所以 `wmfs fs --verbose` 的"超时重试 seq=… → 去重命中"是客户端按"回复里的 ctime 早于重试发出的时刻"推断的，只影响这一行提示。
7. **授权的分工**：xattr 名字空间的规则（`trusted.*` 只给 root、`security.*` 只有 root 能写、`user.*` 只挂在普通文件和目录上且粘滞目录里只有属主能写、ACL 只有属主或 root 能设、默认 ACL 只挂在目录上），以及 chown 的取值规则（只有 root 能改 uid，属主只能把 gid 改成自己所在的组），都由 core 在 authz 管线之前检查，与 Linux VFS 的做法相同；authz 插件只判断属主与 rwx 权限位。`AuthzInput` 不变，ABI 版本不变。
8. **changelog 写在各操作自己的执行器闭包末尾**：与修改同批提交、同批回滚；只有闭包知道 ino、名字和长度。"被拒绝的修改在 audit 打开时也写一条"随 audit 属性在 M12 补。
9. **集群图缓存按 GLOBAL `map_epoch` 失效**：任何改 target、chain、node 记录的批次（包括删目录时删掉 QOS 记录）都在同一批里 `map_epoch += 1`；读者每次点查 `map_epoch`，after_apply 不用通知。changelog 长轮询的唤醒随 M7 的 changelog 端点加入。
10. **查名字之前先查执行权限**：lookup、create、unlink、rmdir、rename（两个父目录）在找目录项之前都先查父目录的执行权限（与 Linux 一致），没有执行权限的人从错误码里看不出目录里有哪些名字。`ResolvePath` 不跟随中间的符号链接（→ `ENOTDIR`），最后一段是符号链接时返回它本身。
11. **`OpenOut.inline`（文件的完整内容）只给能读这个文件的人**：Open 按这次是否读打开决定；Create 打开已有的文件、改 size 的 SetAttr 按调用者有没有读权限决定；新建的文件总带（空内容）。Open 的只读部分在 M4 先做了（`wmfs fs stat` 要用它显示 layout），cap 的签发在 M5。
12. **posix-acl（M10）之前，带扩展 ACL 的文件只有 root 能访问**：posix-mode 先判 root（与 `CAP_DAC_OVERRIDE` 相同），再对带扩展 ACL 的 inode 弃权，全部弃权 = `EACCES`。semantics.md 已写明。M10 的 posix-acl 对 root 也要放行或弃权。
13. **链容量**取有上限的成员里最小的那个，成员全都不限时为 0（不限）。
14. **按 roadmap 留给后面的**：递归计数 RSTAT 与属性继承（M7）、会话驱逐与两阶段（M10）、配额与 path-caps（M10）、回收站（M12）。
15. **开发集群**：M4 起默认装上 posix-mode 与 label-match，集群插件清单变了，旧里程碑建的开发集群要 `wmfs dev down --purge` 后重建；节点不就绪时 `wmfs dev up` 以非 0 退出并提示这条命令（roadmap §0 第 3 条已写）。roadmap 各里程碑的演示在 `scripts/accept.sh Mx` 之前都有一行 `wmfs dev down`。

## 备选方案

- 第 6 条给回复加一个"去重命中"标志：要改帧格式或 `MetaReply`，只为一行提示。否决。
- 第 7 条把 xattr 名字与 chown 的新值交给 authz 插件判定：要改 `AuthzInput` 并升 ABI 版本，而这些规则是固定的 POSIX 规则，不需要插件来改。否决。

## 后果

命名空间与会话的这些细节从 M4 起固定，由金样与测试守住；后面的里程碑只增不改。
