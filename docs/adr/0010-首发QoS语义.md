# ADR-0010 首发 QoS 语义

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 偏离条款：理念文档 4.1 `qos` 钩子"请求进入执行队列"（对所有请求）；6.2 第 1 层"服务端每（租户, 存储类）一个 mClock 三元组 + 令牌桶；作业 id 参与分类"的范围
- 是否触及契约层：否（对外语义写进 semantics.md）
- 批准类别：需确认；确认批次 0（B 栏：知悉即可）
- 相关章节：design.md 4.5、6.1、6.2；semantics.md 第 6 节

## 背景

完整的分布式 mClock（dmClock）需要跨节点交换标签；元数据请求由单 leader 串行执行，排队时间很短。理念文档 6.3 [固定] 承诺 vHDD 类"低优先级"，需要一个真正的机制来兑现。

## 决定

1. mClock 只在**数据节点**执行。队列键 = `(tenant, qos_id, class)`，`qos_id` = `qos` 属性的来源目录；队列内按作业 id 分子队列轮转（作业 id 参与分类）；每队列一个字节令牌桶（`bw_max` × `burst`）；后台任务流量进一个固定的低优先级队列。
2. **成本单位**：一次 IO 的成本 = `1 + bytes / 128 KiB`（4 KiB = 1，1 MiB = 9，4 MiB = 33）；存储类的 `iops_*` 与目录 `qos` 的 `r/l` 都是"成本单位/秒"。`wmfs class show` 显示换算成带宽的结果，semantics.md 写明。
3. 三元组来自存储类的 QoS 包络或目录 `qos` 属性，以**集群级数值**声明，按该存储类当前有 Up target 的数据节点数**静态均分**到每个节点。
4. **优先级**：存储类有 `priority = normal | low`（label 为 hdd 的类缺省 low）。保底阶段不分优先级；权重阶段先只在 normal 队列里选，没有可派发的才选 low 队列（约 10 行）。
5. 睡眠与唤醒由 core 负责（`Mutex<()> + Condvar`，每次入队 `notify_one`），插件的 `enqueue/dequeue` 不阻塞。
6. 各节点的保底欠额经心跳汇总到 leader，`wmfs status` 的 qos 一项显示"实际"份额与欠额。
7. 元数据请求首发不做 QoS（钩子位保留）。

## 备选方案

- dmClock：精确的集群级保底，但实现复杂（跨节点标签传播）。推迟。
- 按"每节点数值"解释：用户设置 `l=500` 却得到 3 × 500 的总上限，反直觉。否决。
- 用真实 IOPS 计数而不是成本单位：大块 IO 与小块 IO 一视同仁，4 MiB 写和 4 KiB 写消耗同样的额度，不合理。否决。
- 元数据 mClock：单 leader 串行执行下收益小。推迟。

## 后果

负载不均时总保底可能达不到、总上限偏保守（semantics.md 写明）；保底欠额作为指标与事件可见；"低优先级"有了具体机制。
