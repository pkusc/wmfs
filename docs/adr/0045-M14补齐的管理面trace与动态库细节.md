# ADR-0045 M14 补齐的管理面、trace 与动态库细节

- 状态：accepted（主管于 2026-11-08 按 design.md 开头的例外条款决定）
  - 内容都是规格漏写的技术细节、新的对外取值的确认（只增）、补做规格已有的功能，以及一处对外说明的如实更正。
  - 不增删功能。
- 日期：2026-11-08
- 性质：
  - 管理面（`wmfs mgr` 的五个插件）、trace、动态库授权插件的补齐；
  - 新的对外取值的确认（只增）；
  - 三处补做规格已有的功能（第 9–11 条）；
  - changelog 保留策略加一个下限（第 12 条，只会多留）。
- 是否触及契约层：**是**。
  - C ABI v1 的 `wmfs_authz_input_v1` 加 `op_flags`（第 1 条）。v1 在 M14 才第一次发布，此前没有人用过。
  - 管理 API 只增的字段、node.toml 的新键（第 2、3 条）。
  - changelog 的保留策略（第 12 条）。
- 相关章节：design.md 2.3、3.7.6、3.11、4.13、4.14、7.1–7.4；semantics.md 第 1、7、9 节；roadmap M14 演示；ADR-0012、ADR-0017、ADR-0027、ADR-0037。

## 背景

M14 实现了这些东西：
- `wmfs mgr`：dashboard、prometheus-exporter、alert、audit-log、webhook；
- span 环形缓冲与 `wmfs trace`；
- C 写的 `.so` 授权插件（`core/hooks/cabi.rs`、`core/include/wmfs_plugin.h`、`docs/plugin-abi.md`）；
- 完整的 nas-safe profile。

三路审查共 57 条意见（11 条 major），修复后验证一轮通过。下面是实现与修复时上报、要主管定的事。

## 决定

### 新的对外取值（确认，只增）

1. **C ABI v1**：
   - `wmfs_authz_input_v1` 在 `op` 之后加 `uint32_t op_flags`：Open/Handle 的 read/write，SetAttr 改了 mode/owner/size/times/times_now 中的哪些。结构 112 字节。
   - 规格原写"另有字段（M14 定）"。头文件给出 `WMFS_OP_*`、`WMFS_OPF_*`、`WMFS_AUTHZ_*` 常量，带 `extern "C"`。
   - 从此冻结。`tests/it/dylib.rs` 用 gcc 编的程序逐字段核对两个 v1 结构的布局。
   - 加载用 `libloading::os::unix::Library::open(…, RTLD_NOW | RTLD_LOCAL)`：缺符号在加载时就失败，不会等到第一次调用。
   - `wmfs join … --dylib <F>` 让新节点带上动态库加入。
2. **管理 API 与 mgr 的新取值**：
   - **管理 API**：
     - `TraceSpan`、`TraceReply`（`trace_id` 是 16 位小写 hex 字符串，见第 4 条）；
     - `NodeInfoReply` 只增 `boot_id`（hex）、`targets`、`pool`、`threads`（ADR-0042 第 4 条说的"随 M14 补上"）；
     - `ClusterReply` 只增 `targets[{id, node, state}]`、`chains`、`sessions`。
   - **mgr 的接口**：
     - `GET /alerts`：`AlertsReply {alerts: [{name, rule, state, since_ms, value, message}], recent}`；
     - dashboard 的代理 `/dash/api`、`/dash/each`。
   - **mgr 的文件与配置**：
     - 审计文件 `audit-YYYYMMDD[.N].log`，100 MiB 轮转；
     - `mgr.toml` 的 `[webhook] url/proxy` 与 `[alert] rules`；
     - `<mgr 目录>/token` 与 `mgr.pid`；
     - 内置告警规则 `dashboard/src/alert/default_rules.toml`；
     - `wmfs dev mgr` 监听 127.0.0.1:19090；`wmfs mgr --key-file`。
   - **changelog 游标**：
     - 新的游标名 `alert`、`webhook`（就是插件名），第一次运行时从最新的 seq 起建；
     - `audit-log` 的游标只由 core 在第一次启用审计时建，mgr 不替它建。
   - **指标**：
     - `wmfs_targets_offline`（leader 上）；`wmfs_clock_skew_seconds` 取绝对值；
     - mgr 自己的 `wmfs_mgr_sink_stalled_seconds` 等。
     - 7.3 推迟到 M14 的五个指标：`target_used_bytes`、`target_capacity_bytes` 在数据节点的 /metrics 里；`quota_used_bytes`、`quota_limit_bytes`、`declared_mismatch_files` 由 mgr 的 exporter 经管理 API 算（4.14 的"集群级指标"）。不在 core 里加常驻的全树扫描。
   - **fail point**：mgr 五个插件的 `plugin.<名字>.<event_sink|mgmt_ext>`。
   - webhook 的 https 靠 ureq 的 rustls feature（design 2.3 下 M1 注记预留的做法），没有另写 TLS 代码。
3. **慢请求阈值**：
   - node.toml 新键 `[obs] slow_meta_ms`、`slow_data_ms`（默认 50、100），server 启动时生效。
   - 3.11 的"可调"取最简单的部署配置。不放进集群运行参数，因为那要改 ClusterSettings 的格式。
4. **trace_id 的两种写法**：
   - trace 端点与 `wmfs trace` 用 16 位 hex：u64 放进 JSON 数字，会被浏览器与 jq 丢精度。
   - changelog 与审计日志里的 `ChangeEvent.trace_id` 是 M7 起就发布的十进制数字，只增规则下不改。
   - `wmfs trace d:<十进制>` 接受后一种写法，semantics.md 第 7 节写明。
5. **`wmfs_quota_denied_total` 的口径**：
   - 客户端用完额度来要（增长为 0、带 want_quota 的 CommitWrite）而没有余量时，也计一次拒绝。
   - 这样内置告警 quota_denied 能覆盖"写到硬限"（4.14 的"硬限拒绝"）。客户端看到的行为不变，仍是 `EDQUOT`。
6. **告警的细则**：
   - **表达式**：在"指标{标签} 比较符 阈值"与"事件类型"之外加 `sum(…)` 与 `rate(…)`。原来的两种写不出 4.14 的几条内置规则：
     - "无元数据 leader"要对全集群求和；
     - "内存池等待""插件超预算速率"是计数器的速率。
   - **事件型规则**：收到匹配的 changelog 记录即 firing；`for`（默认 5 min）内没有新的匹配记录就 resolved。
   - **target 离线**：约 70 s 后告警。target 租约 8 s 过期才算离线，规则再要求持续 60 s。roadmap 演示的"预期"按实测改了。
   - **审计停滞与几个阈值**：
     - "审计消费者 10 分钟没有前进"看 mgr 自己的 `wmfs_mgr_sink_stalled_seconds{sink="audit-log"}`；
     - 内存池等待（> 1/s 持续 60 s）、插件超预算（> 10/s 持续 60 s）的阈值按实现确认；
     - 新增的 `clock_skew`（3.11 的"超过 1 s 告警"）、`changelog_gap`（4.13 的 410 告警）两条规则按实现确认。
   - **退避**：每个 sink 各自退避（1 s 起，上限 5 min）。4.13 只给 webhook 写了退避，现在对所有 sink 都用，一个坏掉的 webhook 不挡审计日志。
7. **dashboard token 读 `/dev/urandom`**：wmfs-mgr 不依赖 core，用不了 core 的随机数。这是 design 0.2 第 7 条的又一个例外。

### 对外说明的如实更正

8. **mgr 停着时没有告警**：
   - 告警是 mgr 自己发的。mgr 停着时，只有 `wmfs status` 的 audit 一行与 `/api/v1/health` 显示"审计消费者落后 N 条"，记录按游标保留、mgr 回来后补写。
   - 生产环境用 systemd 的 `Restart=on-failure` 让 mgr 一直运行（`docs/ops.md`）。
   - mgr 在运行、审计却 10 分钟没有前进时，告警 `audit_stalled`。
   - semantics.md 第 7 节已这样写。

### 补做规格已有的功能（收尾修复）

9. **慢日志的各阶段耗时**：
   - 3.11 要求"超过阈值的请求写一行慢日志（含各阶段耗时：decode、authz、quota、执行、raft 提交、转发、磁盘）"，实现时只记了一个节点上的总耗时。
   - 补上：每个请求只列它走过的阶段。
     - 元数据：decode、authz、quota、执行、raft 提交；
     - 数据：decode、authz、磁盘、转发。
   - 计时用回复句柄里的 `Instant`，与 ADR-0044 第 5 条的延迟统计同一个起点。
   - 需要在 `TxnRequest` 等进程内接口里带上计时，不改线格式。
10. **"协调器积压 1 h 内持续增长"按规格做**：
    - 实现时近似成"积压持续 1 h 不为 0"。可大目录的正常迁移本来就会超过 1 h，会一直误报。
    - 改成：规则进入 pending 时记下当时的积压，满 1 h 时积压比那时多才 firing，否则从现在重新计时。
11. **`GET /api/v1/features`、`POST /api/v1/features/<name>/enable`、`wmfs feature list|enable`**：
    - 7.1、7.2 都列了，roadmap 没排进哪个里程碑。做最小版：
      - list：GLOBAL 已启用的 incompat 特性（首发为空），以及各节点声明支持的特性。
      - enable：对 design 3.2 的预留名（都是二期）回 `FEATURE_UNSUPPORTED`"二期功能"，不认识的名字回 `EINVAL`。

### 技术修补

12. **changelog 至少保留最近 1 万条**：
    - 3.11 的保留策略是"所有游标的最小值之后的全部记录，最多 7 天 / 1000 万条"。
    - 问题：mgr 在运行时它的游标都是最新的，gc 很快把记录修剪光。
      - `wmfs changelog tail` 常常是空的；
      - 依赖 changelog 的测试会偶发失败（M14 实现时 nas-safe 撞到过）。
    - 改成：所有游标都读过的记录，只在比最新的旧 1 万条以上时才修剪。7 天与 1000 万条的上限照旧。
    - 只会多留，不改格式。
13. **行数**：
    - M14 新增约 1,985 行非测试代码：实现约 1,756，审查修复约 230；预算 1,190。
    - 主要多在 mgr 宿主（HTTP、装配、/metrics 抓取合并、sink 退避与 410 缺口）与 alert。
    - Σmax ≈ 37,515（上限 38,000），收尾修复再加约 100 行。roadmap §4 的简化储备没有动用。

## 后果

- 慢日志能看出时间花在哪一步；协调器积压的告警只在真的跟不上时触发。
- mgr 在运行时 `wmfs changelog tail` 仍能看到最近的记录。
- `wmfs feature list` 能看到各节点支持的特性，为二期的滚动升级留好入口。
- C ABI v1 从此冻结。
