# ADR-0020 元数据 KV 布局 v1 与记录版本规则

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 性质：契约层首次定义（理念文档第 3 章"持久化格式"中的元数据 KV 布局、feature flags）
- 是否触及契约层：**是**（不可逆的磁盘格式）
- 批准类别：**需批准**；确认批次 0（B 栏：技术契约）
- 相关章节：design.md 3.2.6–3.2.11

## 背景

元数据 KV 布局一旦有集群在用就不可逆，必须从第一天带记录版本号。执行器闭包只允许点查（ADR-0019），所以布局本身必须让每个写操作都能只靠点查完成：凡是"要找到某某"的地方都要有可以直接拼出来的 key。另外，多个模块（init、placement、rstat、管理 API）会各自读写计数器与 id，初值与"0 表示什么"必须写死。

## 决定

1. key = 1 字节键空间标签 + 字段（整数**大端**，字典序 = 数值序）；value = 1 字节记录版本号 + postcard（INLINE 例外为原始字节）。标签表见 design.md 3.2.7（INODE、DENTRY、XATTR、INLINE、DIRATTR、RSTAT、QUOTA_STATE、LOCKS、SESSION、DEDUP、GC、CHANGELOG、TRASH_INDEX、NODE、TARGET、CHAIN、CLASS、CLASS_NAME、TASK、KEYMETA、DATAKEY、QOS、RECONCILE_Q、CURSOR、EVICTED、**DATAKEY_NAME（0x1C）**、GLOBAL、DEBUG；0x20–0x2E 预留给快照、WASM 等二期功能）。
2. 为了"写操作只做点查"：一个 inode 的全部 xattr 是一条记录（≤ 64 KiB）；一个 inode 的全部锁是一条记录；硬链接反向引用放在 inode 的 `extra_links`；会话持有锁的 inode 列表放在会话记录的 `locked_inos`；目录 `size` = 条目数（rmdir 判空不扫描）；存储类与数据密钥都有"名字 → id"索引（CLASS_NAME、DATAKEY_NAME）。
3. **不变式**：`len(INLINE) ≤ inode.size`，超出部分读为 0；任何改 size 的操作在同一批里维护它。
4. 记录要点：`NodeRecV1.addrs: Vec<(scheme, 地址)>`（不为任何传输留专门字段）；`TargetRecV1.phys_devs`（物理整盘/namespace，ADR-0011）；`StorageClassV1.priority`；`LockRecV1` 的"到文件尾"= `i64::MAX as u64`；`CursorV1 { seq, updated_ms }`；`KeyMetaV1.role` 存 `Role` 的 u8 编码；GLOBAL 有 `plugins`（集群插件清单，ADR-0025）。
5. **id 与计数器初值**：node / target / chain / class / key / datakey 的 id 从 1 开始，0 保留表示"无"（目录的 `class_id = 0`）；changelog 与 reconcile 的 seq 从 1 开始；init 之后 `next_node = 2`、`next_key = 3`、default 类 id = 1、`next_class = 2`；保留 inode 1–15（1 = 根），`next_ino` 从 16 开始、永不复用；epoch 取 `max_epoch + 1`、永不复用；key_id 0 固定是服务端之间用的 Server 角色，不在 KEYMETA 里。
6. DENTRY key = `parent ‖ name`，readdir 按名字字节序分页；客户端为每个目录句柄保存名字分页快照。
7. **插件不能拥有任何键空间**（理念文档 4.3.2）。
8. 版本纪律：已发布的记录结构永不原地修改；改字段 = 新增 `XxxV2` 与新版本号，解码器认识所有旧版本；需要固定数值的字段存 u8（postcard 编码 enum 用的是变体序号）；每种记录一份金样测试（M0 生成）。

## 备选方案

- 每个 xattr 一个 key：需要在执行器里扫描，覆盖层要做三路归并。否决。
- DENTRY key 带名字哈希作为 readdir cookie：多一套哈希规则；名字分页 + 句柄快照更简单。否决。
- 加密属性只接受数字 id、不建 DATAKEY_NAME：演示与日常使用都要先查 id。否决。

## 后果

格式发布后不可逆；新功能通过新标签、新记录版本与 feature flags 引入。
