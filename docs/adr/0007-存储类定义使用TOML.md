# ADR-0007 存储类定义文件使用 TOML（替代示例中的 YAML）

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 偏离条款：理念文档 6.1 的存储类示例使用 YAML
- 是否触及契约层：否
- 批准类别：需确认；确认批次 0（B 栏：知悉即可）
- 相关章节：design.md 6.1

## 背景

`toml` crate 已在依赖清单里（node.toml、插件 manifest 都用它）；新增 YAML 依赖（serde_yaml 已停止维护）不划算。

## 决定

1. `wmfs class create <name> --file class.toml`，字段与理念文档 6.1 对应：`[devices] label/dedicated`、`[redundancy] replica`、`[qos] iops_min/iops_max/bw_min/bw_max/burst/weight/latency_target/priority`、`[placement] failure_domain/locality`、`[lifecycle] tier_to/when`。理念文档的 vhdd 示例里有 `qos: {…, priority: low}`，所以 `[qos]` 里有 `priority = "normal" | "low"`（label 为 hdd 的类缺省 low），对应 `StorageClassV1.priority`。`iops_*` 的单位是"成本单位/秒"（ADR-0010）。
2. `wmfs class update <name> --file class.toml`：只改 `[qos]` → 只下发新份额；改 `replica` 或 `[lifecycle]` → 触发一次整树协调（理念文档 6.2 第 4 层"类的变更触发后台迁移"）；改 `label`/`dedicated`/`failure_domain` → 拒绝（新建一个类再迁移）。

## 备选方案

- 支持 YAML：多一个依赖，无功能收益。
- 存储类完全不可修改：最简单，但调一个 QoS 数字就要换类、迁移全部数据。否决。

## 后果

只是文件格式不同；字段语义不变。
