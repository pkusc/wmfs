# ADR-0011 存储类的设备出口隔离（cgroup io、NVMe WRR）与硬件隔离（NVM Sets、FDP）首发推迟

- 状态：accepted（人类于 2026-10-20 批准）
- 日期：2026-10-20
- 偏离条款：理念文档 6.2 第 2 层"每存储类一个 cgroup（io.weight / io.max）；同一物理盘上的两个类用 NVMe WRR 队列优先级区分"与第 3 层"NVM Sets / FDP"
- 是否触及契约层：否（6.3 [固定] 的诚实承诺照做）
- 批准类别：需确认；确认批次 0（B 栏：知悉即可）
- 相关章节：design.md 6.2、6.3；semantics.md 第 6 节

## 背景

- cgroup v2 的 io 控制器不是 threaded 控制器：同一进程的不同线程不能分属不同 io cgroup，要做就得"每个存储类一个进程"。
- 本机用户 cgroup 只委派了 `cpu memory pids`（已检查），写 `io.max` 需要 root；agent 不运行 sudo。
- Linux nvme 驱动不提供按队列的 WRR 优先级接口。
- 本机这块盘 `max_write_streams = 0`（不支持 FDP）；查询或配置 NVM Sets 需要 NVMe admin 命令（root）。
- 理念文档 6.3 只允许在"独占整盘或整 namespace"时承诺尾延迟；而目录的 `st_dev` 是分区或 LV 级别的——同一块 NVMe 上的两个分区、同一个 PV 上的两个 LV 会得到不同的设备号，直接比较 `st_dev` 会把共享误判成独占。

## 决定

1. 首发唯一兑现的硬件隔离手段是"整盘（或整 namespace）独占"：存储类 `devices.dedicated = true` + 每块盘一个 target。
2. target 启动时把目录的 `st_dev` **解析到物理整盘或 namespace**（读 `/sys/dev/block/<maj>:<min>`：分区取父设备；dm、md、LVM 沿 `slaves/` 递归到底；loop 或解析失败 → unknown；约 40 行纯 `std::fs`），心跳上报 `phys_devs`。一个类只有在它的 `phys_devs` 与其他类不相交、且没有 unknown 时才算 dedicated；unknown 一律按共享处理。结果在 `wmfs status`、`wmfs class show`、dashboard 上显示；声明了 dedicated 却实际共享 → `isolation_downgraded` 告警。
3. `docs/ops.md` 给出"每个存储类一个只带数据角色的 `wmfs server` 进程"的部署方式与带 `IOWeight=`/`IOReadBandwidthMax=` 的 systemd unit 示例（需要管理员以 root 部署）。
4. `wmfs doctor` 报告 FDP/写流与 namespace 数。

## 备选方案

- wmfs 自己写 cgroup：需要 root 并违反"不擅自改系统"。否决。
- 按线程设置 IO 优先级（ioprio）：只对 BFQ/mq-deadline 有效，且不是理念文档要求的机制。推迟。
- 直接比较 `st_dev`：简单，但会把同一块盘上的两个分区误判为独占，承诺了做不到的尾延迟。否决。

## 后果

共享设备上只承诺份额，不承诺尾延迟——与理念文档 6.3 [固定] 一致；本机永远显示 shared。
