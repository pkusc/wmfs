# path-caps 授权插件

**钩子**：authz（altitude 250）　**热路径**：是（每个元数据请求），预算 2 µs/次
**fail point**：`plugin.path-caps.authz`（触发 = 以注入的错误码拒绝这次请求）　**指标**：`wmfs_path_caps_decisions_total{result="allow"|"deny"|"abstain"}`

## 它做什么

把一把客户端 key 限制在若干子树里（例如把一个实验室的机器限制在 `/proj/lab-a`），相当于 CephFS 的 path 限制（design.md 4.3、ADR-0009）。
限制写在 key 的元数据里（复制状态，所有节点看到的一样）：

```bash
wmfs key create lab-a --role client --path /proj/lab-a --path-ro /shared --out lab-a.key
```

`--path` 与 `--path-ro` 在创建时解析成目录的 inode 号，所以目录被 `mv` 之后，限制仍跟着这个目录。

| 请求 | 结果 |
|---|---|
| 对象（目录项操作——查名字、建、删、改名——看父目录，其余看目标本身）在某个允许的子树里 | 放行；那几个子树都是只读的（`--path-ro`）而这是写（建、删、改名、写打开、改属性、写 xattr……）→ `EROFS` |
| 对象是某个允许的子树的**上级目录**，操作是查名字或取属性 | 放行：只为走到子树里去（不能列出上级目录，也不能改它）。这一条由本体判定（见下） |
| 其余 | `EACCES` |

- 经**已经打开的句柄**读写（提交写入的长度、令牌续期……）与 open 相同：路径限制不因为是属主而放松（ADR-0036）。
- 硬链接（`link`）：新父目录要在允许的子树里，**源文件也要**（本体另按"取属性"对源文件核对一次）——不能按 inode 号把子树外的文件
  链接进来。
- 没有限制的 key：弃权（posix-mode、posix-acl 照常判）。
- 管理 API 的按路径查询（`wmfs get`、`wmfs usage`、`wmfs status`）也受限制：有路径限制的 key 只能查它允许的子树，越界回 403。

## 实现说明

"上级目录可以查名字、取属性"要知道每个允许的子树根的祖先，而授权钩子的输入（`AuthzInput`，C ABI v1 也一样）里只有被访问对象自己的
祖先。所以本体先判这一条（按 attr_epoch 缓存的祖先链）：是这种请求时，交给授权插件的连接身份不带路径限制，本插件弃权。本体只会放宽、
从不因为路径限制拒绝；限制本身全在本插件里。
