# zstd 压缩插件

**钩子**：transform（压缩一类，altitude 732，算法编号 2）　**热路径**：是（每个 64 KiB 块），预算 600 µs/块
**fail point**：`plugin.zstd.transform`（触发 = 这一块以注入的错误码失败）　**指标**：`wmfs_zstd_blocks_total{result}`

## 它做什么

与 lz4 一样按块（64 KiB）压缩（先校验和、再压缩、最后加密；读的时候反过来），压缩率比 lz4 高、也慢一些。级别 1–19
（`compress=zstd:3`；只写 `zstd` 就是 3），级别记在文件的存储布局里，同一个文件的所有块用同一个级别。一块压完还超过明文的 7/8
就按原文存（块表里不标"已压缩"）。每个线程缓存一个压缩上下文，不为每块重新分配。

## 配置

没有部署参数：`wmfs set <目录> compress=zstd:3`（M11 起）。新文件（与截断到 0 的文件）立即按新设置写；已有文件由协调器在后台转换，
`wmfs status` 显示还有多少文件与声明不同，`wmfs task list` 显示协调器的进度、速率与积压（`wmfs task set reconciler bw=…` 限速）。

## 诚实说明

压缩后的字节坏了，要么解不开（当坏块处理），要么解出不同的明文——随后被校验和查出来；不会把错误的数据交给应用。
物理占用（`du` 看 target 目录）随转换逐步下降；逻辑用量（`wmfs usage`、配额）一直按文件的表观大小计，不因压缩而变小。
