# fifo 调度插件

**钩子**：qos（altitude 401；qos 只允许一个活跃，与 mclock 二选一）　**热路径**：是，预算 2 µs/次
**fail point**：`plugin.fifo.qos`（本体包在入队外层，触发 = 这个请求以注入的错误码失败）　**指标**：`wmfs_fifo_depth`、`wmfs_fifo_served_total`

## 它做什么

数据节点收到的读写请求先进 QoS 队列，再由 io 线程按插件给的顺序执行（design.md 4.5）。fifo 是最简单的一种：**先来先做**，不分租户、
不看目录的 `qos` 属性。给不需要 QoS 的部署用（`minimal` profile）；有份额与上限的 mclock 在 M13。

插件只决定"下一个做谁"，不睡觉也不阻塞：队列空的时候本体的 io 线程在条件变量上等，有新请求进来就被叫醒（睡眠与唤醒归本体，所以
插件写错也只会派发不准，不会忙等或丢失唤醒）。

## 配置

没有部署参数，也不消费任何目录属性——所以只启用 fifo 时 `wmfs set qos=…` 会被拒绝（没有插件消费它），而不是被静默忽略。
