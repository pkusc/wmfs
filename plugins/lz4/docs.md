# lz4 压缩插件

**钩子**：transform（压缩一类，altitude 731，算法编号 1）　**热路径**：是（每个 64 KiB 块），预算 150 µs/块
**fail point**：`plugin.lz4.transform`（触发 = 这一块以注入的错误码失败）　**指标**：`wmfs_lz4_blocks_total{result}`

## 它做什么

数据写进 chunk 文件之前，按块（64 KiB）压缩：顺序由本体固定——先算明文的校验和，再压缩，最后（开了加密的话）加密；读的时候
反过来。一块压完还超过明文的 7/8（随机数据、已经压缩过的文件）就按原文存、在块表里不标"已压缩"，读它的时候也不用解压。
省下的空间靠稀疏文件真正省下来：每块在文件里的位置固定，只写压缩后的那几个字节。

lz4 很快、压缩率一般；要更高的压缩率用 zstd（`compress=zstd:3`）。

## 配置

没有部署参数：`wmfs set <目录> compress=lz4`（M11 起）。新文件（与截断到 0 的文件）立即按新设置写；已有文件由协调器在后台转换
（`wmfs status` 看进度，`wmfs task list` 看速率；一直写打开的文件会被跳过，单独计数）。

## 诚实说明

压缩后的字节坏了，要么解不开（当坏块处理），要么解出不同的明文——随后被校验和查出来；不会把错误的数据交给应用。
