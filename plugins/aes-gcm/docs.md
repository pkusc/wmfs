# aes-gcm 加密插件

**钩子**：transform（加密一类，altitude 761，算法编号 1）　**热路径**：是（每个 64 KiB 块），预算 100 µs/块
**fail point**：`plugin.aes-gcm.transform`（触发 = 这一块以注入的错误码失败）　**指标**：`wmfs_aes_gcm_blocks_total{dir}`、`wmfs_aes_gcm_auth_failures_total`

## 它做什么

数据写进 chunk 文件之前，按块（64 KiB）用 AES-256-GCM 加密——变换链的最后一步（先算明文的校验和、再压缩、最后加密），原地加密、
不多拷贝一次。每块用一个现取的 12 字节随机 nonce（绝不从版本号推导），nonce 与 16 字节的认证 tag 存进块表。附加数据里有集群、
文件、epoch、chunk 与块的编号：块被挪到别的文件、别的位置或别的集群就解不开，读的时候 tag 不符一律当坏块处理（换副本、报错），
不会交出错误的数据。

数据密钥用 `wmfs datakey create <名字>` 建（打印数字 id）：元数据 leader 随机生成 32 字节的密钥，用集群主密钥派生的 `K_wrap` 加密
包裹后存进元数据（DATAKEY 与名字索引 DATAKEY_NAME）、经集群图下发；数据节点解包后只放在内存里。包裹与解包也用本插件（key_id 0），
所以停用本插件时既不能建数据密钥，也不能设置 `encrypt`。

## 配置

没有部署参数：`wmfs set <目录> encrypt=tenant:<名字>`（M11 起；数据密钥要已存在）。新文件立即加密、并且**不再内联**进元数据库（内联
内容存在元数据里、不加密）；已有文件由协调器在后台转换，已有的内联小文件被转成加密的 chunk。

## 诚实说明

- 只加密 chunk 数据：文件名、长度、属性、目录结构在元数据库里是明文。
- 开启加密之前写入的内容、以及开启之后转换完成之前往已有文件里新写的内容，在转换完成前仍是明文；一直写打开的文件不会被转换
  （`wmfs status` 单独计数）。旧的明文版本在 gc 删掉旧 epoch 之后才离开磁盘（`wmfs task run gc`），元数据库的空闲页里也可能残留旧明文。
- 同一把密钥用随机 nonce 的安全上限约 2^32 次加密（约 256 TiB 的 64 KiB 块）；超过 64 TiB 之后建议换一把新的数据密钥（docs/ops.md）。
- 没有 TLS：数据在网络上是明文（与 design.md 的首发信任边界相同，ADR-0009）。
