# cache-local-nvme 缓存插件（客户端）

**钩子**：cache_store（客户端；与 cache-memory 二选一，挂载参数 `--cache local-nvme:DIR[:SIZE]`）　**热路径**：是，预算 50 ms/次（本地盘 IO）
**fail point**：`plugin.cache-local-nvme.cache_store`（本体包在每次调用外层，触发 = 这次读当作没命中、这次放不放）
**指标**：`wmfs_cache_local_nvme_total{result}`（hit / miss）、`wmfs_cache_local_nvme_bytes`

## 它做什么

把从数据节点读回来的块缓存在本机的一个目录里（通常放在本地 NVMe 上，比内存缓存大得多），下次读同一块直接从本地盘取（design.md 4.11）。
默认容量 50 GiB，按总字节"最久没用的先淘汰"。

```
wmfs mount 127.0.0.1:19100 ~/wmfs-mnt --cache local-nvme:/nvme/wmfs-cache:100G
```

- 缓存的键带着文件的 change_id：文件一被改写，旧的块就再也查不到（cto：打开文件时拿到最新的 change_id），不会读到旧数据。
- 只缓存已经提交的数据；本挂载自己还没写出去的数据从写回缓冲里读，不进缓存。
- 一块一个文件（`<ino>-<change_id>-<块号>`），淘汰就是删文件。

## 诚实说明

- **缓存里是明文**：解密在数据节点上做，客户端收到、缓存的都是明文——包括只有属主能读的文件与加密目录（`encrypt=tenant:…`）里的文件。所以
  缓存目录建成 0700、块文件 0600；目录已经存在时，它必须属于挂载的用户、组和别人都没有任何权限，否则拒绝挂载（`chmod 700 DIR` 之后再挂）。
- **一个缓存目录只给一个挂载用**：挂载期间拿着目录里 `.lock` 的独占锁，第二个挂载用同一个目录会被拒绝（两个挂载会互相清掉、覆盖对方的块）。
- **挂载时清空**：上次挂载留下的缓存不用（不做崩溃恢复，避免任何"它还新不新"的推理）。只删这个插件自己命名格式的文件，目录里别的东西不碰。
- 缓存目录所在的盘满了、读写出错：只当没命中，照常从数据节点读。
- strong 目录与 `--cache none` 不用缓存（direct_io）。
